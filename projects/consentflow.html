ConsentFlow Patient-Centric Health Data Control

ConsentFlow is a full-stack healthcare consent management platform built to give patients genuine ownership over their electronic health records. The system uses a microservices architecture with a dedicated AI service for risk assessment, a gateway API that enforces role-based access, and a blockchain-ready audit trail that ensures every consent grant, modification, or revocation is tamper-evident and time-stamped.

The project addresses a real gap in healthcare interoperability. Existing systems treat consent as a binary checkbox rather than a dynamic, revocable, patient-controlled permission layer. ConsentFlow models consent as a living document where patients can grant, restrict, and revoke access per provider, per data type, and per time window.

Features

What makes it different

Dynamic Consent Engine

Patients grant or revoke access per provider, per data type, and per time window. Every change is logged with a tamper-evident timestamp rather than overwriting the previous state.

Role-Based Access Control

Four distinct portals for patients, providers, administrators, and the API gateway, each enforcing least-privilege access with JWT-backed session tokens and RBAC middleware.

Emergency Override Protocol

Clinicians can invoke a time-limited emergency bypass under active audit logging. The override window, reason, and provider identity are all immutably recorded.

AI Risk Scoring Service

A dedicated FastAPI microservice assesses consent-request risk in real time, flagging unusual access patterns, bulk data requests, or off-hours provider activity before access is granted.

FHIR R4 Interoperability

Data is structured around FHIR R4 resources, making the platform compatible with existing EHR systems and national health information exchanges without a custom adapter layer.

Blockchain Audit Trail

Every consent lifecycle event is appended to a cryptographically chained audit log, giving regulators, patients, and auditors a complete and uneditable history of all access decisions.

Known Limitations

  • Blockchain integration uses an append-only PostgreSQL audit log; a distributed ledger (Hyperledger Fabric) is scoped for a future hardening pass.
  • AI risk-scoring is currently rule-based; an ML anomaly detection layer is the natural next extension.
  • FHIR R4 mapping covers core resources (Consent, Patient, Practitioner); extended types such as MedicationRequest and DiagnosticReport are not yet mapped.
  • Frontend is functional and complete; a dedicated UX polish pass would be the next step before a production deployment.
